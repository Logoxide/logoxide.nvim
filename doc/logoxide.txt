*logoxide.txt*  Find, search, and complete Bible references

==============================================================================
CONTENTS                                                         *logoxide*

  1. Setup ........................................... |logoxide-setup|
  2. Commands ..................................... |logoxide-commands|
  3. Telescope ................................... |logoxide-telescope|
  4. Language server ................................... |logoxide-lsp|
  5. Bible text ....................................... |logoxide-text|

logoxide.nvim runs logoxide-lsp (completion, hover, inlay hints, symbols,
diagnostics, go-to-references, and search code actions) and searches your
workspace with the topos CLI. With a Bible (a folder of USX files), hover
shows a reference's text and go-to-definition opens the whole book.

==============================================================================
1. SETUP                                                   *logoxide-setup*

With lazy.nvim: >lua
  {
    'Logoxide/logoxide.nvim',
    main = 'logoxide',
    build = ':LxBuild!',
    dependencies = { 'nvim-telescope/telescope.nvim' }, -- optional
    ft = { 'markdown', 'text' },
    cmd = { 'LxSearch', 'LxQuery', 'LxExplicitOverlap', 'LxAnyOverlap',
            'LxExactOverlap', 'LxInside', 'LxExcludeOverlap', 'LxFileReferences',
            'LxDirReferences', 'LxCopy', 'LxInsert', 'LxBuild', 'LxLspStart',
            'LxRead', 'LxBibleAdd', 'LxBibleSearch', 'LxBibleRemove' },
    opts = {
      bible = '~/Bibles/BSB',
      settings = { format = 'abbreviation', ['inlay-hints'] = 'never' },
    },
  }
<
Building needs Rust (https://rustup.rs): |:LxBuild| runs `cargo install`
into the plugin's build/ folder: logoxide-lsp (the language server) from a logoxide
checkout and topos (the CLI) from a topos checkout (`source`), or from GitHub.
logoxide-lsp can't be installed from GitHub until logoxide is published, so set
`source` to checkouts for now. If the binaries are missing, `setup()` builds
them (see `auto_build`). Binaries on your PATH work too.

`require('logoxide').setup(opts)` takes (the defaults): >lua
  {
    -- logoxide-lsp's settings, overriding ~/.config/topos/config.toml (the
    -- CLI's keys), like { format = 'abbreviation',
    --   ['psg-fmt'] = { join_adjacent = true }, ext = 'md,txt',
    --   ['inlay-hints'] = 'changed' | 'always' | 'osis' | 'usfm' | 'never'
    --     | a template's name, or a template like '{first:1}'
    --       (see |logoxide-templates|),
    --   ['reference-diagnostics'] = 'info' | 'hint' | 'never',
    --   ['reference-diagnostics-template'] = their text: a template's
    --     name, or a template (the reference by default),
    --   hover = { 'text', 'name', 'abbreviation', 'osis', 'book',
    --             'testament', 'genres', 'verses', 'location', 'written',
    --             'bcv', 'translation' } }
    settings = {},
    -- A folder of USX files, one book each (see |logoxide-text|)
    bible = nil,
    -- More Bibles by name: { KJV = '~/Bibles/KJV' } or
    -- { KJV = { path = '~/Bibles/KJV', aliases = { 'AV' } } }
    -- (see |logoxide-translations|)
    bibles = {},
    -- The Bible for references that name none: `bible`'s, else the first
    -- of `bibles` by name (|:LxBible| changes it)
    default_bible = nil,
    -- Bibles whose text hover also shows, like { 'BSB', 'KJV' }
    hover_bibles = nil,
    -- How hover and completion documentation show a passage's text:
    -- `trim` leaves out its leading whitespace (a heading displayed as
    -- '\n{text}' would start with a blank line); `max` is how many
    -- characters (bytes) show before ` …`, false for no limit; `title`
    -- is the first line (see |logoxide-translations|), false for none
    hover = { trim = false, max = 2000,
              title = '**{reference}** ({translation})' },
    -- How Bible text is written and colored (see |logoxide-markup|)
    markup = {
      verse_numbers = { show = true, display = '[{verse}]' },
      chapter_numbers = { show = true, display = '{name} {chapter}' },
      headings = { show = true, display = '{text}' },
      notes = { show = false, display = '[{text}]' },
      words_of_jesus = { show = true, display = '{text}' },
      added = { show = true, display = '{text}' },
      divine_name = { show = true, display = '{text}' },
      quotes = { show = true, display = '{text}' },
      width = nil,
      indent = { q1 = 0, q2 = 2, q3 = 4, q4 = 6 },
    },
    -- Named templates: code actions, :LxCopy's forms, and inlay hints
    -- (see |logoxide-templates|)
    templates = {},
    -- Completion offers the chapter or verse already typed, first
    -- (`Matthew 1` offers Matthew 1, then Matthew 10, ...), so its text
    -- shows in the documentation
    complete_typed = true,
    -- Search EPUBs in the workspace too; their
    -- references open in a read-only buffer of the book's text
    -- (logoxide-file:///…/Gill.epub) at the reference. Off by default: a book
    -- takes a moment to read the first time (then it's cached, with the
    -- topos CLI's cache)
    epub = false,
    -- Search PDFs the same way, building logoxide-lsp with PDF support
    -- (MuPDF: a C compiler, and longer)
    pdf = false,
    -- Commentaries whose notes hover shows after a passage's text: true
    -- for all the project's, or ids like { 'mhcc' } (|logoxide-commentaries|)
    commentaries = nil,
    -- A note also covers the verses after it up to the commentary's
    -- next (|logoxide-commentaries|)
    stretch_notes = false,
    -- Hovering a Strong's number (G25, H430) shows its dictionary entry
    -- (|logoxide-commentaries|)
    strongs = false,
    lsp = {
      enabled = true,
      filetypes = { 'markdown', 'text' },
      -- The folder searched by references, the code actions, and the commands
      root_markers = { '.git', '.obsidian' },
      inlay_hints = true,
      -- Older place for the settings above (the top-level ones win)
      settings = {},
    },
    -- Binary paths; nil uses the plugin's build, then your PATH
    cmd = { lsp = nil, cli = nil },
    -- What :LxBuild builds from: a topos checkout (logoxide beside it), or
    -- { topos = '~/src/topos', logoxide = '~/src/logoxide' }; nil for GitHub
    source = nil,
    auto_build = true,
    -- Past the end (or start), where |:LxNextBook| and the others go:
    -- books 'wrap' (Revelation → Genesis) or 'stop'; chapters, verses, and
    -- headings 'next' (into the next book or chapter), 'wrap' (this book's
    -- or chapter's first), or 'stop'
    navigation = { books = 'wrap', chapters = 'next', verses = 'next',
                   headings = 'next' },
    -- The verse marked in |:LxParallel|'s other windows
    -- (LogoxideParallelVerse, linked to |hl-CursorLine|): `highlight`, a
    -- group to link to, or false for no mark; or `color`, a background
    -- color ('#2a3340') or a highlight definition
    parallel = { highlight = nil, color = nil },
    -- 'auto' (Telescope if installed), 'telescope', or 'quickfix'
    picker = 'auto',
    -- searches reuse the CLI's cache for unchanged files (`--cache`);
    -- false never does, nil leaves it to the CLI's config.toml
    cache = true,
  }
<
The CLI also reads ~/.config/topos/config.toml, so named queries (`-q`)
and custom data work in the commands too.

==============================================================================
2. COMMANDS                                             *logoxide-commands*

Results open in Telescope, or the quickfix list without it. Searches cover
the language server's workspace folder (or a root marker, or the cwd).

                                                                  *:LxCopy*
:LxCopy [x]          Copies the reference under the cursor's passage into a
                        register (the unnamed one by default), in the form
                        chosen from |logoxide-templates| (Telescope previews
                        each; just the passage's text without any).
                                                                *:LxInsert*
:LxInsert            Writes it with the template chosen (those with an
                        `action`), like its code action.

`settings['reference-diagnostics-template']` and `settings['inlay-hints']`
can name a template too (with its markup), or be one, shown on one line for
each reference: `'{first:1}'` is the passage's first verse.

                                                                *:LxSearch*
:LxSearch [paths]    Every reference in the workspace (or the paths).

                                                                 *:LxQuery*
:LxQuery {options}   A search with the CLI's options, completed with <Tab>:
                        `:LxQuery -g Wisdom`, `:LxQuery --nt -b John`,
                        `:LxQuery -q pauline` (a named query).

:LxExplicitOverlap [passage]                        *:LxExplicitOverlap*
                        References that name a verse of the passage; whole
                        chapters don't count (`-o`).
:LxAnyOverlap [passage]                                  *:LxAnyOverlap*
                        References that share any verse with it.
:LxExactOverlap [passage]                              *:LxExactOverlap*
                        References that are exactly it, however written.
:LxInside [passage]                                          *:LxInside*
                        References entirely inside it.
:LxExcludeOverlap [passage]                          *:LxExcludeOverlap*
                        References that share no verse with it.

Without a passage, these use the reference under the cursor. Passages are
completed with <Tab> (`John 3:` lists every verse).

:LxFileReferences [passage]                          *:LxFileReferences*
                        The references in the current buffer (its unsaved
                        text too). In Telescope the prompt is a passage that
                        narrows them as you type: `mat 1` keeps the
                        references inside Matthew 1, a book alone (`mat`)
                        keeps the whole book's, and a prompt starting with
                        `-` is the CLI's options (`-g Gospels`). The
                        passage given starts the prompt; in the quickfix
                        list it narrows the results once.
:LxDirReferences [passage]                            *:LxDirReferences*
                        The same, for every file under the current
                        directory (|:pwd|).

                                                              *:LxLspStart*
:LxLspStart          Starts logoxide-lsp for the current buffer, whatever its
                        file type (an unnamed buffer too), or restarts it if
                        it is running (re-attaching its buffers). Neovim can't
                        route diagnostics to an unnamed buffer, so the plugin
                        asks for them itself as you edit.

                                                                 *:LxBible*
:LxBible [name]      References that name no Bible use this one (a name
                        or alias from `bible` and `bibles`; without one,
                        choose with |vim.ui.select()|). It lasts until
                        Neovim quits; `default_bible` sets it for good.

                                                                  *:LxRead*
:LxRead [book] [name]
                        Opens a whole book (`logoxide://BSB/JHN`): `John`,
                        `1 cor`, or `JHN`, in the Bible named after
                        it (`:LxRead John KJV`), else the current whole
                        book's Bible, else the default. Without a book,
                        chooses one: in Telescope, previewing each book as
                        it reads (colored as in a whole book), else with
                        |vim.ui.select()|. Takes a modifier to open it in a
                        split (`:vertical LxRead Romans`). Books and Bible
                        names are completed with <Tab>. Starts logoxide-lsp if it
                        isn't running (as `:edit logoxide://...` does).

                                    *:LxNextBook* *:LxPrevBook*
                              *:LxNextChapter* *:LxPrevChapter*
                                  *:LxNextVerse* *:LxPrevVerse*
                              *:LxNextHeading* *:LxPrevHeading*
:[count]LxNextBook   In a whole book, go to the next book of its Bible
:[count]LxPrevBook   (or the previous one), the next chapter (its label),
:[count]LxNextChapter
:[count]LxPrevChapter
:[count]LxNextVerse  the next verse, or the next heading (with a count,
:[count]LxPrevVerse  that many). Headings on consecutive lines (a psalm's
:[count]LxNextHeading
:[count]LxPrevHeading
                        book, range, and title) are one. Past the end (or
                        start), `navigation` says where: by default books
                        wrap (Revelation → Genesis), chapters and headings
                        go on to the next book, and verses to the next
                        chapter (and on to the next book). Each move is in
                        the |jumplist|. For mappings: >lua
  vim.keymap.set('n', ']v', '<Cmd>LxNextVerse<CR>')
<
                                                              *:LxParallel*
:LxParallel [name]   In a whole book (`logoxide://BSB/JHN`), opens the
                        same book in another Bible in a split, at the verse
                        under the cursor, and keeps the two on the same verse
                        as either cursor moves, into another book too
                        (|:LxNextBook| in one opens the next book in both,
                        when the other Bible has it). A cursor already in
                        the verse stays where it is. The verse the cursor
                        is on is marked in the other windows (just the
                        verse, not its whole line; see `parallel`). From a
                        window that is already parallel, a third Bible
                        joins them. Takes a modifier for the
                        split (`:horizontal LxParallel KJV`; vertical by
                        default).

                                                            *:LxBibleSearch*
:LxBibleSearch {words}
                        Searches the catalogs (eBible.org's and fetch.bible's
                        translations, or those `logoxide.toml` names) by name,
                        abbreviation, or language, and installs the Bible
                        chosen with |vim.ui.select()|. Runs `lx` in the
                        current folder: its `logoxide.toml`, else the
                        library's own. logoxide-lsp restarts to read it.

                                                               *:LxBibleAdd*
:LxBibleAdd {source} Installs a Bible: a logoxide package's git URL (its
                        newest release), or `ebible:<id>` / `fetch:<id>`
                        (imported from eBible.org or fetch.bible).

                                                            *:LxBibleRemove*
:LxBibleRemove {id}  Removes a package from `logoxide.toml` (`lx clean
                        --remove` deletes versions nothing uses).

                                                                 *:LxBuild*
:LxBuild[!]          Builds logoxide-lsp, lx, and topos if they are missing (!
                        rebuilds), then starts the language server. It
                        runs `cargo install` into the plugin's build/
                        folder, from GitHub or `source`.

`:checkhealth logoxide` shows which binaries are used and whether they run.

                                                            *logoxide-lua*
Each command is a function of `require('logoxide')` too, for mappings and
scripts. They take what the command takes (a string, or a list of words for
the searches); the moving ones take a count (1 by default): >lua
  local logoxide = require('logoxide')
  logoxide.search(paths)                   -- :LxSearch
  logoxide.query('-g Wisdom')              -- :LxQuery
  logoxide.explicit_overlap(passage)       -- :LxExplicitOverlap, and
  -- any_overlap, exact_overlap, inside, exclude_overlap
  logoxide.copy(register)                  -- :LxCopy
  logoxide.insert()                        -- :LxInsert
  logoxide.file_references(passage)        -- :LxFileReferences
  logoxide.dir_references(passage)         -- :LxDirReferences
  logoxide.read(book, mods)                -- :LxRead ('John KJV', 'vertical')
  logoxide.next_book(count)                -- :LxNextBook, and prev_book,
  -- next_chapter, prev_chapter, next_verse, prev_verse, next_heading,
  -- prev_heading
  logoxide.bible(name)                     -- :LxBible
  logoxide.parallel(name, mods)            -- :LxParallel
  logoxide.bible_search(words)             -- :LxBibleSearch
  logoxide.bible_add(source)               -- :LxBibleAdd
  logoxide.bible_remove(id)                -- :LxBibleRemove
  logoxide.lsp_start()                     -- :LxLspStart
  logoxide.build(force)                    -- :LxBuild[!]
<
The plugin maps no keys. For moving through a whole book, for example: >lua
  local logoxide = require('logoxide')
  local function map(lhs, move)
    vim.keymap.set('n', lhs, function() move(vim.v.count1) end)
  end
  map(']b', logoxide.next_book)
  map('[b', logoxide.prev_book)
  map(']c', logoxide.next_chapter)
  map('[c', logoxide.prev_chapter)
  map(']v', logoxide.next_verse)
  map('[v', logoxide.prev_verse)
  map(']h', logoxide.next_heading)
  map('[h', logoxide.prev_heading)
<

==============================================================================
3. TELESCOPE                                           *logoxide-telescope*

`setup()` loads the extension when Telescope is installed: >vim
  :Telescope logoxide                          " every reference
  :Telescope logoxide query args=-g\ Wisdom
  :Telescope logoxide explicit_overlap passage=John\ 3:16
  :Telescope logoxide any_overlap              " the reference under the cursor
  :Telescope logoxide file_references passage=mat\ 1
<
The pickers are `search`, `query`, `explicit_overlap`, `any_overlap`,
`exact_overlap`, `inside`, `exclude_overlap`, `file_references` and
`dir_references` (|:LxFileReferences|), and `copy` and `insert` (|:LxCopy|). From Lua: >lua
  require('telescope').extensions.logoxide.exact_overlap({ passage = 'Rom 8:28' })
<
==============================================================================
4. LANGUAGE SERVER                                           *logoxide-lsp*

Go to references (|grr|, or Telescope's `lsp_references`) lists every
reference in the workspace that is exactly the one under the cursor. The code
actions (|gra|) reformat it the way completion writes it (or every reference
in the file), or search for it by explicit overlap, any overlap, exact
overlap, or inside it, opening the results like the commands do. Hovering a
reference shows its text (with a `bible`), full name, abbreviation, OSIS id, book, testament, genres,
verses, and where it is (`settings.hover` picks which, and their order: the
default is every one but `written` and `bcv`); hovering a reference that
doesn't exist says what does (`John 3 has 36 verses`). Each reference has an
information diagnostic with how it's written in your format (`John 3:16`);
references that don't exist get a warning. Inlay
hints show the formatted reference where it's written differently.

==============================================================================
5. BIBLE TEXT                                               *logoxide-text*

Set `bible` to a folder of USX files, one book each (`JHN.usx`,
`44JHNBSB.usx`, or any name with a `<book code>` inside), as Paratext, the
Digital Bible Library, and eBible.org publish them. The folder's name names
the Bible. Its files are left out of workspace searches. Then:

- Hovering a reference (|K|) shows the passage's text, with the heading
  before it, cut after `hover.max` characters (2000; false for no limit).
  `hover.trim = true` leaves out its leading whitespace, like the blank line
  a heading or chapter label displayed as '\n{text}' starts with.
- Completing a chapter or verse shows its text as the item's documentation
  (with 'completeopt' "popup", or your completion plugin's documentation).
  The chapter or verse already typed is offered first (`Matthew 1` before
  `Matthew 10`), so its text shows too; `complete_typed = false` leaves it
  out.
- Go to definition (|CTRL-]|, or |vim.lsp.buf.definition()|) and go to
  declaration (|vim.lsp.buf.declaration()|) open the whole book at the passage, in a buffer named like `logoxide://BSB/JHN`. You
  can also open one with |:LxRead| or `:edit logoxide://BSB/JHN`. The
  buffer can't be changed (its 'filetype' is `logoxide`, and it wraps long
  paragraphs). |:LxNextBook|, |:LxNextChapter|, |:LxNextVerse|,
  |:LxNextHeading|, and their `:LxPrev*` move by book, chapter, verse, and
  heading (map them as
  |logoxide-lua| shows). Its symbols
  (|gO|, or Telescope's `lsp_document_symbols`) are its chapters and verses.
- In that buffer, go to references (|grr|) on a verse lists every reference
  that names it in your workspace (explicit overlap: `John 3` doesn't count
  for John 3:16); on a chapter's label, every reference that shares a verse
  with the chapter. Hovering a verse there says how many references name it,
  and in how many files (`???` if searching takes more than half a second;
  what was read is cached, so hovering again gets further).

                                                    *logoxide-translations*
Several Bibles: `bible` (named after its folder) and `bibles` (named by their
keys, with `aliases`) are translations. A reference followed by one's name or
alias, ignoring case (`John 3:16 KJV`, `John 3:16, KJV`, `John 3:16 (AV)`),
uses that Bible; other references use `default_bible`. Then:

- Hover (on the reference or the name) shows that Bible's text, then the
  `hover_bibles`; with several Bibles, each text is labeled with its name.
- Go to definition opens its book (`logoxide://KJV/JHN`).
- Completion offers the names after a reference (`John 3:16 K` gives `KJV`).
- The reference is checked against that Bible's own verse counts (read from
  its USX), and a warning names it: `John 3:17 does not exist in the KJV`.
- Insertions use it; a reference that names none offers one per Bible
  (`Insert Callout (KJV)`), and `{bible}` in `display` is the Bible's name.
  `{translation}` is its name too, unless it's the default Bible and the
  reference names none: then it's nothing, along with the brackets around
  it and the space before it, so `'> [!bible] {reference} ({translation})'`
  writes `John 3:16 (KJV)` for the KJV and `John 3:16` for the default.
- Hover's first line is `hover.title`, the same way: `{reference}`,
  `{bible}` (the Bible whose text shows first), and `{translation}` (the
  Bible the reference names). By default `'**{reference}** ({translation})'`;
  false leaves the line out. The `translation` field of the `hover`
  setting is a line naming it (`- Translation: KJV`), when there is one.
  A text is labeled with its Bible's name only when hover shows several
  (with `hover_bibles`).

                                                    *logoxide-commentaries*
Commentaries and dictionaries come from the project (`lx add` them like any
package). With `commentaries` (true, or a list of ids), hovering a reference
shows, after the Bible text, each note the commentaries have on its verses,
labeled with the commentary's name and the verses the note covers:
`MHCC (John 3:16-18)`. After eight notes from one commentary the rest are
counted. A verse a commentary skips has no note unless `stretch_notes` is
true: then a note also covers the verses after it up to the commentary's
next note in the chapter. With `strongs = true`, hovering a Strong's number (an uppercase `G`
or `H` and its digits: `G25`, `G0025`, `H430a`) shows its entry in each of
the project's Strong's dictionaries that has it, under the number and its
headword. Notes and entries are written with the `markup` settings, without
verse numbers.

                                                          *logoxide-markup*
`markup` says how Bible text is written and colored, in whole books, hover,
completion documentation, and templates. It has one table per element:

  Key               What it is                                Shown by default
  verse_numbers     a verse's number, a label                 yes
  chapter_numbers   a chapter's number, a label on its own    yes
                    line (whole books)
  headings          section headings, on their own line       yes
  notes             footnotes                                 no
  words_of_jesus    words of Christ ("red letters")           yes
  added             translators' additions (KJV italics)      yes
  divine_name       LORD in small capitals                    yes
  quotes            quotations other than words of Jesus      yes

Each table takes:

  show        `true` or `false`. Hidden headings and notes are left out;
              hidden others are plain text (no `display` or color).
  display     How it is written.
              - verse_numbers and chapter_numbers: a label, with `{verse}`
                (`16`, or `4-5` for a bridge), `{chapter}`, `{name}` (`John`),
                and `{book}` (`JHN`). Defaults: `'[{verse}]'` and
                `'{name} {chapter}'`.
              - The others: a template with `{text}` (the element's text) and
                `{name}`, like `'## {text}'` or `'“{text}”'`. Default
                `'{text}'` (notes: `'[{text}]'`). The template's text is
                glued to the element's words.
  color       A color name or `'#rrggbb'` (the foreground), or a highlight
              definition like `{ fg = 'gray', italic = true }` (see
              |nvim_set_hl()|).
  highlight   Or a highlight group to use, like `'Comment'` (instead of
              `color`).

For example: >lua
  markup = {
    verse_numbers = { color = 'blue', display = '{verse} ' },
    chapter_numbers = { display = 'Chapter {chapter}', highlight = 'Title' },
    headings = { display = '## {text}', highlight = '@markup.heading' },
    notes = { show = true, display = '({text})', color = { fg = 'gray', italic = true } },
    words_of_jesus = { color = 'red', display = '“{text}”' },
    added = { highlight = 'Comment' },
  }
<
`markup.width` (a number, not a table) breaks lines longer than that many
characters at a space, in whole books, hover, and templates; nil (the
default) leaves lines whole, and a book buffer wraps them at the window's
width. 'textwidth' doesn't do this: it only applies as you type or format
(|gq|), and a book buffer can't be changed. >lua
  markup = { width = 80 }
<
Poetry is a line each, with a blank line between stanzas. `markup.indent`
(a table of numbers) is how many spaces each kind of line starts with, by
its USFM marker: by default a verse's first line (`q1`) at the margin and
the lines that continue it two spaces further in each level (`q2`, `q3`,
`q4`). The keys you set replace those, and other markers can be added:
`qr` (Selah), `qm1`, `pi1` (indented paragraphs), `li1` (lists); an
unnumbered `q` is `q1`, and an OSIS Bible's `<l level="2">` is `q2`. The
first line of a hover's passage starts at the margin, and a line broken at
`markup.width` goes on at the margin. >lua
  markup = { indent = { q1 = 2, q2 = 6, qr = 10 } }
<
Without `color` or `highlight`, each links to a group of your colorscheme:

  Element           Highlight group                        Default link
  verse_numbers     @lsp.type.verseNumber.logoxide      |hl-Number|
  chapter_numbers   @lsp.type.chapterNumber.logoxide    |hl-Title|
  headings          @lsp.type.heading.logoxide          |hl-Title|
  notes             @lsp.type.note.logoxide             |hl-Comment|
  words_of_jesus    @lsp.type.wordsOfJesus.logoxide     DiagnosticError
  added             @lsp.type.added.logoxide            @markup.italic
  divine_name       @lsp.type.divineName.logoxide       @markup.strong
  quotes            @lsp.type.quote.logoxide            @markup.quote

In whole books the colors come from logoxide-lsp's semantic tokens, so the text
has no markup. In hover (and completion documentation), a passage is a
```logoxide code block: Neovim hides its first line, whose info string says
what to color, and the plugin colors the block the same way (its text is
`LogoxideBibleText`, Normal's color, rather than a code color). Completion
documentation is a plain ```logoxide block, since completion plugins like
blink.cmp show the first line instead of hiding it; the colors are in the
item's `data.tokens`. To color it in blink.cmp, set its documentation `draw`: >lua
  completion = {
    documentation = {
      draw = function(opts) require('logoxide').blink_draw(opts) end,
    },
  }
<
Other items are drawn as usual.

`markup` can also go in ~/.config/topos/config.toml (as `[markup]`, without
colors), where the server reads it like the other settings.

                                                       *logoxide-templates*
`templates` are named forms of a passage, by name: >lua
  templates = { callout = { ... }, verse = { ... } }
<
One with an `action` is a code action (|gra|), like "Insert callout"; any is
a form |:LxCopy| offers, and `settings['reference-diagnostics-template']` and
`settings['inlay-hints']` can name one. Each
takes:

  display       What it writes: `{text}` (the passage), `{first:N}` and
                `{last:N}` (its first or last N verses), `{reference}` (as
                formatted, `John 3:16`), `{osis}` (`John.3.16`), `{usfm}`
                (`JHN 3:16`), `{bible}`, and `{translation}` (see
                |logoxide-translations|). Default `'{text}'`.
  line_prefix   Written before each line of the text, like `'> '`.
  markup        `markup` for this template, over the one above (the same
                keys, without colors).
  action        Its code action (|:LxInsert| offers them too):
                - `'insert'`: on the lines below the reference ("Insert
                  callout")
                - `'replace-line'`: in place of the reference's whole line
                  ("Replace line with callout")
                - `'replace'`: in place of the reference, keeping the rest
                  of its line ("Replace with callout")
                - nil (the default): none, for |:LxCopy|, diagnostics,
                  and inlay hints

For example, an Obsidian callout, a quote in place of the reference, and the
first verse without its heading as each reference's diagnostic: >lua
  templates = {
    callout = {
      display = '> [!bible] {reference}\n{text}',
      line_prefix = '> ',
      markup = { headings = { show = false }, verse_numbers = { display = '{verse}' } },
      action = 'insert',
    },
    -- `See John 3:16 here` → `See “For God so loved ...” (John 3:16) here`
    quote = {
      display = '“{text}” ({reference})',
      markup = { verse_numbers = { show = false }, headings = { show = false } },
      action = 'replace',
    },
    verse = { display = '{first:1}', markup = { headings = { show = false } } },
  },
  settings = { ['reference-diagnostics-template'] = 'verse' },
<
The old `insertions` list is an error that says how to write it as
`templates`: `replace = 'line'` is `action = 'replace-line'`, `replace =
'inline'` is `action = 'replace'`, and nothing is `action = 'insert'`.
